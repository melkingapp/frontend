## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2024-05-16 - Ensure Accessibility and Focus Management in Forms
**Learning:** For dynamic settings forms, associating helper text or validation errors using static strings is inadequate, especially when elements are conditionally rendered. Wrapping components like `SettingsInput` and `NotificationToggle` in `forwardRef` allows libraries like `react-hook-form` to properly manage focus on validation failures, while dynamically constructing `aria-describedby` based on available IDs prevents dangling references that confuse screen readers.
**Action:** When creating reusable, conditional form components, always use `forwardRef`, dynamically construct `aria-describedby` arrays based on component states (e.g. `${id}-error` or `${id}-desc`), add `role="alert"` for error containers, and ensure decorative icons are explicitly hidden with `aria-hidden="true"`.
