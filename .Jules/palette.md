## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2026-04-15 - [UX] Accessible Form Group Inputs
**Learning:** For custom mapped-array input groups (like `RadioGroup` and `CheckboxGroup`), using `role="group"` with an `aria-labelledby` pointing to the pseudo-legend provides the best screen reader experience without the visual regressions sometimes caused by semantic `<fieldset>` elements overriding Tailwind's box sizing. Furthermore, to support `react-hook-form`'s auto-focusing on validation errors, `forwardRef` must be conditionally passed *only to the first input in the mapped array* (`ref={index === 0 ? ref : null}`), otherwise React will continuously override the ref on every loop iteration, breaking the focus mechanism.
**Action:** Always implement this conditional ref pattern combined with `aria-labelledby` and `aria-describedby` on custom React form group components intended for use with libraries like `react-hook-form`.
