## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2024-06-12 - Floating Action Button Accessibility
**Learning:** Custom interactive components like floating action buttons with dropdown menus (often built with `div` and custom state) frequently miss crucial semantic relationships in this codebase. Without `aria-expanded`, `aria-controls`, and `role="menu"`, screen readers cannot announce the state or link the button to the revealed menu list. Furthermore, keyboard users lack focus indicators (`focus-visible:ring-2`) on these custom elements, making it impossible to know when they are focused via Tab navigation.
**Action:** Always link custom dropdown toggles to their corresponding list container using `aria-controls="[list-id]"` and dynamically track the open/closed state with `aria-expanded={isOpen}`. The container must have `role="menu"` (or `listbox`) and a matching `id="[list-id]"`, with list items acting as `role="menuitem"`. Provide localized `aria-label` and `title` for icon-only toggles, and hide decorative nested icons via `aria-hidden="true"`. Finally, enforce standard app focus styling using utility classes like `focus:outline-none focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-[#D3B66C]`.
