## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2024-05-12 - Dynamic aria-describedby and forwardRef in Custom Inputs
**Learning:** When building custom form inputs (like `SettingsInput`), wrapping them in `forwardRef` is crucial for form libraries (like `react-hook-form`) to manage focus on invalid fields correctly. Moreover, when dynamically associating help text and error messages with the input via `aria-describedby`, it is important to generate a fallback unique ID using `useId()` and conditionally combine the IDs into a space-separated string, matching the conditions used to render the actual DOM elements to avoid dangling references. Adding `role="alert"` ensures screen readers announce the error immediately, and `aria-hidden="true"` on decorative icons prevents redundant reading.
**Action:** Always implement `forwardRef` for custom input components to ensure focus management works with form libraries, and construct `aria-describedby` dynamically using arrays that filter out falsy values before joining them.
