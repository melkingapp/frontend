## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2024-05-25 - Public Header Mobile Menu ARIA & Focus Enhancements
**Learning:** For components that conditionally render overlays (like the mobile menu Drawer `Dialog` in `MobileMenu.jsx`), proper accessibility dictates linking the trigger button to the overlay via `aria-controls` matching the overlay's `id`, along with conditionally updating `aria-expanded`. Additionally, custom icon-only buttons built with standard Tailwind require explicit hover and focus utility classes (like `focus:outline-none focus-visible:ring-2 focus-visible:ring-[#D3B66C]`) combined with properly localized `title` and `aria-label` attributes (e.g. "باز کردن منو", "بستن منو") to accommodate both screen readers and desktop pointer users intuitively.
**Action:** Always link toggle buttons and their target floating/modal elements with matching `aria-controls` and `id` pairs, bind `aria-expanded` to the active state, and apply localized `title` attributes and focus visible styles to icon-only buttons as standard practice when designing or refactoring responsive navigation.
