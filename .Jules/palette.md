## 2024-05-24 - Accessibility improvements for Form Inputs
**Learning:** Adding `aria-describedby`, `aria-invalid`, and `aria-required` to input fields significantly improves screen reader experience by linking errors and requirements to the input itself. Using `forwardRef` is crucial for libraries like `react-hook-form` to manage focus correctly (e.g., focusing on the first invalid field).
**Action:** Always wrap form inputs with `forwardRef` and ensure error messages are programmatically linked to their inputs via ID.
## 2024-05-17 - Dynamic `aria-describedby` in Conditional Settings Form Components
**Learning:** In reusable form components (like `SettingsInput` and `NotificationToggle`), conditionally rendered elements such as error messages and helper text can cause dangling `aria-describedby` references if not carefully constructed. If the error text rendering relies on an `error` prop being truthy, the ID generator used for `aria-describedby` must perfectly mirror this condition (e.g., using array filtering like `[errorId, descId].filter(Boolean).join(' ') || undefined`) to ensure the array remains valid and empty states correctly remove the attribute. Furthermore, wrapping error messages in elements with `role="alert"` drastically improves screen reader notification when an error dynamically appears.
**Action:** Always link validation feedback and helper texts to inputs using dynamic unique IDs and `aria-describedby` with matching conditional statements, add `role="alert"` for form errors, and use `aria-hidden="true"` on non-semantic decorative SVG icons inside the components to prevent redundant announcements.
