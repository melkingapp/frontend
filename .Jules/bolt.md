## 2024-06-03 - Referential Equality in Redux Selectors
**Learning:** Returning a literal fallback array or object (e.g., `return data || []`) directly from `useSelector` breaks referential equality because it creates a new reference on every store update. This forces unnecessary component re-renders. The same issue applies to fallback assignments that are not memoized, destroying the purpose of any subsequent `useMemo` hooks that use the variable as a dependency.
**Action:** Always define a constant empty array/object outside the component/hook (e.g., `const EMPTY_ARRAY = [];`) and use it as the fallback in `useSelector` to maintain referential stability. When assigning variables from `useSelector` data that might use a fallback based on conditional logic (e.g., `data.transactions || EMPTY_ARRAY`), always wrap the assignment in `useMemo`.
