## 2024-05-15 - Stable Array Fallbacks inside Redux Selectors
**Learning:** Returning inline literal array fallbacks like `|| []` inside `useSelector` callbacks triggers a re-render for every Redux dispatch because the selector returns a new reference even if the state value is strictly falsy.
**Action:** Extract `[]` to a module-level constant `const EMPTY_ARRAY = [];` and use that stable reference as the fallback inside `useSelector` and other array assignment operations that rely on referential equality.
## 2024-05-15 - Redux selector array stability and GitHub Actions migration to pnpm
**Learning:** Returning inline literal array fallbacks like `|| []` inside `useSelector` callbacks triggers a re-render for every Redux dispatch because the selector returns a new reference even if the state value is strictly falsy. Furthermore, when fixing Node 20 deprecation warnings in CI by migrating `npm ci` to `pnpm install`, using `actions/setup-node` with `cache: pnpm` requires a lockfile (like `pnpm-lock.yaml`) to exist, and `package-lock.json` must be safely removed if `pnpm` is explicitly adopted.
**Action:** Extract `[]` to a module-level constant `const EMPTY_ARRAY = [];` and use that stable reference as the fallback inside `useSelector` to maintain referential equality. For GitHub CI migrations to `pnpm`, add `pnpm/action-setup@v4` with a specific version, change Node setup to `cache: pnpm`, and update execution scripts to `pnpm run`.
